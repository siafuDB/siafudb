# AGENTS.md — siafudb

Rules for AI agents and people working in this repository. They layer on the
org-wide guide, [nyuchi/.github AGENTS.md](https://github.com/nyuchi/.github/blob/main/AGENTS.md).
Where the two conflict, this file wins. Read `README.md` and the ADRs in
`docs/adr/` first.

## What this repo is

SiafuDB: an embedded property graph database for device, edge and Web3, a
Bundu Foundation open project under Apache-2.0, still in Phase 1. Read the
README's status block before describing what exists. There are no Python, Node
or Go bindings yet, so do not document them as shipped.
The Graph Sync Protocol itself lives in
[`siafuDB/siafudb-gsp`](https://github.com/siafuDB/siafudb-gsp), pinned by git
`rev` in `Cargo.toml`. This repo holds the adapter.

| `crates/siafudb-ffi`    | UniFFI bindings for Swift and Kotlin (`scripts/ffi/`).              |

## Build, lint, test

These are the commands CI runs (`.github/workflows/ci-platforms.yml`). Rust
must be 1.99 or newer; JavaScript tooling needs Node 24 or newer (`.nvmrc`).

```bash
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace

# Browser profile (needs: rustup target add wasm32-unknown-unknown)
cargo build -p siafudb-core --no-default-features --features browser --target wasm32-unknown-unknown

# engine/ must still match the crates.io 0.6.2 packages
scripts/ci/check-engine-pin.sh

# Web package
npm ci
npm run typecheck --workspaces --if-present
npm test --workspaces --if-present
npm run build --workspaces --if-present
npm run test:e2e --workspaces --if-present   # Playwright, needs Chromium
```

Rebuilding the web package regenerates
`packages/siafudb-web/src/wasm/siafudb_wasm.d.ts`; CI fails if the committed
copy is stale, so commit it with the change that altered it.

## Conventions

- **Rust first.** New engine, sync and binding code is Rust. TypeScript is for
  the browser package only; Swift and Kotlin are generated by UniFFI and are
  never hand-written wrappers.
- **`engine/` is frozen.** Do not sync it to upstream Grafeo. A change to it is
  recorded in `engine/CHANGES.md` (Apache-2.0 section 4(b)), and CI fails when
  it drifts from the pinned crates.io packages without that record.
- **Conventional Commits** on every commit and PR title
  (`.github/workflows/pr-title-lint.yml`), with `Refs #n` or `Closes #n`.
- **Pin third-party GitHub Actions to full commit SHAs.**
- **Prefer safe Rust.** Any `unsafe` needs a comment saying why it is sound.
  `#[allow(...)]` needs a same-line reason.
- **Keep the browser build working.** Anything reachable from the `browser`
  feature of `siafudb-core` must build for `wasm32-unknown-unknown`.
- **No secrets in the repo.** npm publishing uses trusted publishing over OIDC,
  with no long-lived token (`.github/workflows/publish.yml`).

## Releases

A release is a version bump merged to `main`: `release.yml` reads
`[workspace.package] version` in `Cargo.toml` and, when `v<version>` is not yet
tagged, tags it and cuts the GitHub release, which then runs `publish.yml`.
A merge that leaves the version alone releases nothing. Never push a tag by
hand and never change the version unless the task is a release. Publishing a
version to npm or crates.io is permanent.

## Out of bounds

- Do not run or alter `publish.yml` or `release.yml`, and do not bump the
  version, except in a release PR the owner asked for.
- Do not weaken encryption, signature or tamper checks in `siafudb-store` or
  the sync adapters.
- Do not touch DNS, hosting or infrastructure. Do not edit `LICENSE`,
  `THIRD_PARTY_NOTICES` or `engine/UPSTREAM.md` except as part of a recorded
  licence or provenance change.
